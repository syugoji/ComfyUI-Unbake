# civitai-recipe-sync

Raindrop に溜めた Civitai の画像ブックマークを、**LoRA Manager のレシピへ一括変換する**スクリプト。

ブックマークした画像1枚につき、
「元画像 → 生成情報の抽出 → 足りないモデル情報をハッシュで復元 → レシピとして保存」
までを自動で回す。

## これが解く問題

Civitai で「あとで再現したい」と思った画像をブックマークしても、
実際に再現しようとすると **モデルとLoRAを1つずつ手で探し直す**ことになる。
名前が一致しない、同名の別バージョンがある、消えている、といった理由で毎回詰まる。

このスクリプトは、**画像に埋め込まれた生成情報**と **SHA-256 ハッシュ**を索引にして、
その突き合わせを機械にやらせる。ハッシュで引くので、モデル名が変わっていても同定できる。

## 動かすのに要るもの（4つ揃わないと動かない）

| # | 必要なもの | 補足 |
|---|---|---|
| 1 | **Raindrop.io のアカウントとテストトークン** | 対象コレクションに Civitai の画像URLを入れておく |
| 2 | **本スクリプト** | このディレクトリ |
| 3 | **改造版 LoRA Manager** | 同梱の [`../comfyui-lora-manager/`](../comfyui-lora-manager/)。**本家では動かない**（後述） |
| 4 | **ComfyUI 本体が起動していること** | 既定 `http://127.0.0.1:8188`。LoRA Manager の API を叩くため |

加えて **Civitai のアカウント**（成人向けを含める場合は API キー）と、
**レシピの置き場所**（LoRA Manager が読むフォルダ）が要る。

> ### なぜ本家 LoRA Manager では動かないのか
> このスクリプトは起動時に `/api/lm/health-check` を叩き、
> `recipe_generation_source_policy == "embedded-first-v1"` を要求する。
> この識別子は**本家 1.1.9 には存在しない**（改造版が追加したもの）。
> 本家に向けると起動時チェックで止まる。

## 置き場所

**このディレクトリをフォークと並べて置く。** つまり ComfyUI なら

```
ComfyUI/custom_nodes/comfyui-lora-manager/   ← フォーク
ComfyUI/custom_nodes/civitai-recipe-sync/    ← ここ
```

フォークの「Raindrop 同期」ボタンは、既定でこの位置のスクリプトを探す
（設定の「同期スクリプトのパス」で別の場所も指定できる）。

`__init__.py` が入っているのは**カスタムノードだからではない**。
ComfyUI は `custom_nodes/` 直下のすべてのディレクトリを読み込もうとし、
`__init__.py` が無いと起動のたびに警告とスタックトレースを出す。
中身は空でノードを1つも登録しない。

## セットアップ

```
cp config.example.json config.json
```

LoRA Manager の設定画面（ライブラリ → Raindrop 同期）から入力する場合、
`config.json` は要らない。画面で入れた値が環境変数として渡る。

`config.json` を開いて埋める。必須は3つ。

| キー | 環境変数 | 中身 |
|---|---|---|
| `raindrop_token` | `RAINDROP_TOKEN` | Raindrop の設定 → Integrations → For Developers → Create new app → テストトークン |
| `collection_id` | `RAINDROP_COLLECTION_ID` | 対象コレクションを開いた時のURL末尾の数字 |
| `recipe_dir` | `LORA_RECIPE_DIR` | LoRA Manager のレシピ保存フォルダ（絶対パス） |

任意:

| キー | 環境変数 | 既定 |
|---|---|---|
| `civitai_api_key` | `CIVITAI_API_KEY` | 無し。成人向けや一部のフォールバックで必要 |
| `comfy_base_url` | `COMFY_BASE_URL` | `http://127.0.0.1:8188` |
| `lora_models_dir` | `LORA_MODELS_DIR` | `recipe_dir` の一つ上 |
| `checkpoint_models_dir` | `CHECKPOINT_MODELS_DIR` | 無し。**未設定だとチェックポイントの名前解決が効かない** |
| `prompt_lora_fallbacks` | (config.json のみ) | 空 |

**優先順位は 環境変数 > `config.json` > 既定値。**
`config.json` は `.gitignore` 済み。別の場所に置きたい場合は `CIVITAI_SYNC_CONFIG` にパスを渡す。

`recipe_dir` と `checkpoint_models_dir` は環境ごとに違う。
LoRA Manager 側の `settings.json` / `extra_model_paths.yaml` を見て合わせること。

## 実行

```
pip install requests
python civitai_image_download.py
```

必須項目が欠けていれば、何が足りないかを出して止まる。

初回だけ既存レシピの移行がまとめて走る。全件を一度に処理したい場合:

```
CIVITAI_REIMPORT_BATCH_SIZE=0 python civitai_image_download.py
```

## Civitai へのアクセスについて

**公開API（`/api/v1/…`）だけを使う。**

Civitai の利用規約 §11.4 は自動アクセスを「明示的に提供するインターフェース」に限っている。
そのため、以前のバージョンにあった

- 内部API `api/trpc/image.getGenerationData` / `api/trpc/image.get`
- 画像ページのHTMLを正規表現でスキャンして画像URLを抜く経路

は**どちらも撤去した**。現在使うのは次の公開エンドポイントだけ。

| エンドポイント | 用途 |
|---|---|
| `GET /api/v1/images?imageId=..&withMeta=true` | 画像本体URL・生成情報・使用モデルID |
| `GET /api/v1/model-versions/{id}` | モデルバージョンの詳細とDLリンク |
| `GET /api/v1/model-versions/by-hash/{sha256}` | ハッシュからモデルを同定 |

**撤去による回収率の低下は無い**（2026-07-26・69枚のペア実測）。
詳細は [`../comfyui-lora-manager/CHANGES-FORK.md`](../comfyui-lora-manager/CHANGES-FORK.md) の §7。

実測で分かった注意点:

- `imageId` フィルタは**公式ドキュメントに記載が無いが機能する**
- **`withMeta=true` を付けないと `meta` が空**で返る
- `meta` は `{"id": .., "meta": {..}}` と**1段包まれて返ることがある**

### レート制限とAPIキーの扱い

§11.4 が求めているのは経路だけではない。自動アクセスは
「公開APIなど明示的に提供するインターフェース経由で、**それぞれ自分自身の有効な
資格情報を用い、かつ適用されるレート制限の範囲内で**」に限られる。

問題は、**Civitai が公開APIのレート制限値を公表していない**ことにある
（`developer.civitai.com` のガイドにも requests/min の記載が無い）。
守るべき数字が公表されていない以上、こちらで保守的に振る舞うしかない。
そこで次を実装してある。

- ホストごとに最小間隔を空ける（既定 1 秒）
- 429 / 503 は `Retry-After` を尊重し、無ければ指数バックオフ
- リトライを使い切った 429 は**同期全体を中止**する（終了コード 2）
- 401 / 403 は単発ではスキップに留める（見られない画像でも返るため）が、
  連続で既定 5 回を超えたら中止する

**APIキーは `Authorization: Bearer` ヘッダでのみ送る。** URL のクエリ文字列
（`?token=...`）には載せない。クエリはアクセスログ・プロキシ・Referer に残るためで、
Civitai 自身も API トークンを「パスワードと同様に扱え」と案内している。

### 成人向けコンテンツ

`include_adult_content`（既定 **false**）で切り替える。

有効にすると `nsfw=X&browsingLevel=255` が付き、Civitai 側であなたが成人向けを
非表示にしていても取得する。**既定では付けない。** ブックマークに成人向け画像が
含まれていて再現できない場合だけ有効にすること。

## Raindrop へのアクセスについて

Raindrop は上限 **120 requests/分** を明示し、429 とともに `X-RateLimit-*` を返す。
このスクリプトは残枠が僅少になったらリセットまで待つ。

**規約上、注意が要るのはここから。** Raindrop の利用規約は

> API への濫用または過度に頻繁なリクエストは、そのアカウントの API アクセスの
> 一時的または恒久的な停止につながることがある

と定めており、**第三者製のツール経由の利用も利用者を拘束する**と明記している。
つまり**停止されるのはこのツールの作者ではなく、あなたのアカウント**である。
自動同期の間隔を短くしても得るものは無い（ブックマークが増えていなくても
毎回コレクション全件を読み直す）ので、既定より短くすることは勧めない。

### トークンについて

セットアップで使うのは Raindrop の**テストトークン**である。

- Raindrop の公式ドキュメントが標準としているのは**アプリケーションを登録した
  OAuth 認証**で、テストトークンについての記述は無い。個人が自分の環境で使う分には
  実務上問題ないが、公式の想定手順ではないことは知っておくとよい
- テストトークンは通常**無期限で、アカウントの全権限を持つ**。自動同期を有効に
  すると常時保存されることになる
- 不要になったら Raindrop の設定画面から失効させること

### トークンの保存場所

LoRA Manager の設定画面から入力した場合、トークンは **`settings.json` へ平文で
保存される**（Civitai APIキーと同じ扱い）。ブラウザへは返さないが、
ファイルを見れば読める。同期スクリプトを直接叩く場合は `config.json` か環境変数。
どちらも `.gitignore` 済みだが、**画面共有・スクリーンショット・録画では映る**。

## 自動同期（無人実行）

LoRA Manager 側の設定で有効にすると、ボタンを押さなくても同期が走る。**既定は無効。**

無人実行では次が変わる。

| 挙動 | 手動実行 | 無人実行 |
|---|---|---|
| 不足LoRAの自動ダウンロード | 設定に従う（既定 有効） | **強制的に無効** |
| 同期の間隔 | 押したとき | 最小 1 時間（設定で短くできない） |

自動ダウンロードを無人時に止めているのは、Civitai 利用規約 §11.9 が
「bot・スクリプト・その他あらゆる自動化を用いてシステムや統計を操作すること」を
禁じているため。**このツールでダウンロード数という統計に自動で加算されうる経路は
モデル取得だけ**なので、そこだけ人がいる時に限る。

コマンドラインから無人モードで叩く場合は `--unattended` を付ける。

## `prompt_lora_fallbacks` について

プロンプトの `<lora:名前:強度>` にしか痕跡が無く、Civitai からも消えた LoRA を、
利用者が自分で用意したミラーから復元するための**枠だけ**を用意してある。**既定は空**。

`url` と `sha256` の両方が必須で、ダウンロード後に実ファイルのハッシュを照合し、
一致しなければ破棄する（すり替え防止）。

**何を登録するかは利用者の責任。** 配布物には何も入れていない。
実在人物の肖像を学習した LoRA など、権利・肖像権の問題があるものは登録しないこと。

## テスト

```
cd civitai-recipe-sync
python -m pytest tests/ -q
```

外部APIへのアクセス方針（レート制御・認証・成人向け・無人実行）を反証つきで
固定してある。ソース走査で「クエリ文字列に鍵を載せる行」と
「ラッパーを迂回した `requests.get/post`」が無いことも見ている
（実行時には気づけないため）。

## 制限

- **Windows 前提の箇所がある**（レシピの `file_path` をバックスラッシュで書く）
- 画像が**非公開・削除済み**なら取れない。生成情報を投稿者が伏せている場合も同じ
- レシピの再取り込み（reimport）は**レシピIDが変わる**
- レート制限に当たると**同期を中止する**（終了コード 2）。
  途中まで保存されたレシピはそのまま残るので、時間を置いて再実行すればよい
