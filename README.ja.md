0.# ComfyUI-Unbake

*[English → `README.md`](README.md)*

> "You can't unbake a cake." — このノードは、その「できないはず」をやる。

**画像1枚から、それを作った ComfyUI のワークフローを組み直す。**
そして**軸を1本だけ動かして何本も回し、結果を並べて比べる。**

Civitai の画像でも、手元の PNG でも、ComfyUI 自身の出力でも、
パネルへ落とすところから始まる。

---

## やらないこと

意図的に持たない機能を、仕様として先に書いておく。
「まだ無い」ではなく「**作らない**」である。

- **モデルの閲覧・検索・整理** — LoRA Manager。
- **モデルのプレビュー画像や説明の管理** — LoRA Manager。
- **Civitai の閲覧クライアント** — 画像1枚を指して渡す以上のことはしない。
- **学習・マージ・量子化** — 生成の再現と比較だけを扱う。
- **判定だけを外へ出すライブラリ** — それは
  [genrecord](https://github.com/syugoji/genrecord) の仕事（AGPL-3.0 ＋商用）。
  あちらは「再現できるか」を決め、こちらは「実際に組んで回す」。

---

## 3つの語

| 層 | 語 | 何のことか |
|---|---|---|
| 入力 | **Generation Record**（短く `Record`／日本語では「**記録**」） | 1枚の画像を作った条件の記録。Civitai の画像・A1111 の PNG・ComfyUI の出力・**LoRA Manager のレシピ**、どれも供給源になる |
| 計画 | **Replay Manifest** | その記録から組み上げた実行計画。**何が満たせて何が足りないか**が付いている |
| 比較 | **Sweep** | 軸を宣言して何本も回し、並べて比べる |

**入力を「レシピ」と呼ばないのは、そう呼ぶと入力元が1つのツールに縛られるから**である。
受け取る4経路のうち、レシピと呼べるのは1つだけ——ComfyUI の出力も、Civitai の画像も、
A1111 の PNG もレシピではない。**「レシピ」は LoRA Manager が書き出したものを
名指しするときに使う。** 総称は Generation Record（短く Record／日本語では「記録」）。

## 何ができるか

### 1. 再現する

画像を落とすと、記録を読んでワークフローを組む。組んだうえで
**「そのまま再現できる」「近似になる（理由つき）」「足りない」**を判定する。

判定は導入済みの実体（`/object_info`）と突き合わせて出す。
**名前が一致することと、ComfyUI が受け取れることは別**なので、
別名表まで見たうえで「投入できる」ところまで確かめる。

足りないものは、手段ごとに仕分けて出す
（Civitai から落とせる／既知モデル台帳から落とせる／手動でしか入らない／手がかりが無い）。
**「配布されていないので落としても使えない」ものは、そう言う。**

### 2. Sweep する

**Sweep は比較ではなく、比較の正しさの保証である。**

- 軸は5種（`checkpoint` / 生成パラメータ / LoRA 強度 / プロンプト追記 / プロンプト差し替え）
- 回し方は4種（**seed だけ** / 単軸×seed / 直積 / 直積×seed。上限 500セル）
- 各軸は**2つ以上の異なる値**と**ちょうど1つの baseline** が要る
- **宣言した軸以外が動いていたら例外を投げる**（`assertOnlySweepInputsChanged`）
- 中断しても**再開できる**し、既にある出力は**作り直さない**
- **自動スコアは参考表示だけ。勝者は人間が選ぶ。**

画面の順序が、そのまま上の主張になっている。

> 雛形を選ぶ → **軸を確かめる** → **検査する（まだ投げない）** → 回す → 並べて見る

**「検査する」が「回す」の前に在る。** 検査を通るまで「回す」は押せない——
順番を入れ替えると、**間違った比較を先に見せてから正しさを検査する**ことになり、
見てしまった絵の印象は取り消せない。検査は投げずに計画を全部組み、
セル数と所要の見積もりを出す。

**一番上の雛形は「seed だけ」。** 軸を1本も動かさず、記録の seed から4本回す——
「あの1枚はたまたま良かっただけではないか」は再現の作業で最も多い問いなので、
最初に置いてある。**専用の画面は作っていない**（雛形が1つ増えるだけ）——
機能ごとに UI を足すと、覚えることが増えて Sweep 全体が使われなくなる。
記録に seed が無いときは、**そのことを説明に書く**（元の1枚と同じものは1枚も出ない）。

雛形は記録から自動で出る（seed だけ・LoRA強度・LoRA×CFG・2本バランス・CFG×Steps・Prompt追記）。
白紙から軸を書ける人はいないので、**「これで回す」か「ここを直す」から始められる**ようにしてある。
値は `ラベル = 値` を1行ずつ、基準の行頭に `*`。基準を自動で真ん中にしないのは、
**値を1つ足しただけで基準が動くと、前の実験と比べられなくなる**から。

回す側の決めごとも4つある。

- **同じ組み合わせは回し直さない。** 判定は値ではなく**組み上がったグラフ**の指紋で行う。
  飛ばした件数は「飛ばした」として表に出す——**回した回数ではなく、出た画像が揃っていること**が
  比較の前提なので、黙って減らさない。
- **1セルごとに保存する。** 途中で閉じても、次に開くと続きから回る。投げ済みのものは
  **投げ直さず待つ**。
- **投げたか判らないセルを「失敗」と混ぜない。** 混ぜて再送すると二重生成になり、
  どちらが記録の再現なのか判らなくなる。
- **基準のセルに画像が無ければ、そう言う。** 何と比べているのかが無い状態で
  絵だけ並べると、「良く見えたもの」を勝ちにしてしまう。

**Sweep にかけられるのはレシピ由来の記録だけ。** 捕捉した画像は実行したグラフを
そのまま持っていて、それを振るのは別の機構になる。かけられない記録には
**押せないボタンではなく理由**が出る。

出たセルは**そのまま記録として取り込める**。ただし焼かれ方は2つに分かれていて、
**実行したグラフは ComfyUI 自身が PNG の `prompt` チャンクへ書く**（実測: 出力の
100%が持つ）。Unbake が `extra_pnginfo` へ入れているのは **Sweep の印だけ**で、
グラフはそこに入っていない。捕捉 → Sweep → また捕捉、で輪が閉じるのは前者のおかげ。

### 3. 落として登録する

パネルへ落とせるものは3つあり、**中でやっていることは全部違う**。

| 落とすもの | 来るもの | 何をするか |
|---|---|---|
| **ComfyUI の出力** | `/api/view` の URL | 実体を取って**そのまま捕捉する**（グラフが埋まっているので組み直さない） |
| **手元の画像ファイル** | バイト列 | PNG のメタから読む。**捕捉** |
| **LoRA Manager のレシピ**（`.recipe.json`） | バイト列 | グラフがあれば使い、無ければ**組む**。**再現** |
| **Civitai の画像ページ** | **URL だけ**（バイト列は来ない） | ID を取って API から取り直し、**再構成** |

**「捕捉」と「再現」は質的に別物である。**
ComfyUI が出した画像には実行したグラフがそのまま埋まっているので、読むだけでよい。
一方レシピは、**手元の346件で実行グラフを持っていたのは48件（14%）だけ**で、
残りは組み立てが要る——それをやるのがこのツールの中核である。

捕捉の経路は、**自分の出力を記録 → Sweep → また記録**という輪を閉じる。

**Civitai の投稿URL（`/posts/…`）は、意図して受けない。** 投稿は絵を複数持てるので
URL だけでは1枚に決められず、黙って1枚目を選ぶと**静かに違う絵を再現する**。
「投稿を開いて目当ての絵を押し、そのページの URL（`/images/…`）を落としてください」と出す。

### 0. 自分の記録が最初から出る

設定でフォルダを指すと、そこの `*.recipe.json` と**対の参照画像**を走査して一覧に出す。
落とすまで空、では 346件を毎回落とすことになり、実際には使えない。

- **読み取り元は読み取り専用。** LoRA Manager の recipes フォルダを指しても、
  **一切書き込まない。** Unbake が作るものは別のフォルダへ出す（設定で分けてある）。
- **一覧は判定を付けずに出す**（`まだ組んでいない`）。346件ぶんの判定は1件ずつ
  グラフを組んで初めて出るもので（実測で全件8秒前後）、開いた瞬間にやると画面が固まる。
  組むのは Sweep を開いたときで、そこでは1件で足りる。
- **稼働中の LoRA Manager は補助にしかしない。** ディスクの記録が常に優先で、
  API から足せるのは**フォルダに無い id だけ**。記録には出所（`folder` / `lora-manager`）が
  必ず付く——どこから来たかが読めなければ、食い違いは「無かったこと」になる。
- **読めなかったフォルダを「0件」と混ぜない。** 理由を画面へ出す。

**鍵は書けるが読み出せない。** Civitai の API キーと Raindrop のトークンは入力できるが
**二度と表示されない**——出るのは「入っているか」と「文字数」だけ。表示する導線を作ると、
それがそのまま開発者ツール・画面共有・録画への漏洩経路になる。文字数を出すのは、
貼り付けが途中で切れた事故（「設定したのに認証が通らない」の正体）に気づけるようにするため。
保存先は ComfyUI の user ディレクトリで、**この拡張のフォルダの外**＝バージョン管理に入らない。

**参照画像はパスで引けない。** 画面へ渡すのは記録の id だけで、パスの解決はサーバ側でやる。
`?path=` を受ける口を作らないので、走査対象の外を読ませる余地が原理的に無い。

### 4. 実際に回して確かめる（試行）— **中核にあるが、まだ画面に出ていない**

判定は「組めるか」までしか言わない。**組めることと、回して同じものが出ることは違う。**
試行は組んだものを **4つの seed** で投げる——1本目は記録に書いてある seed
（＝完全再現の候補）、残り3本は無作為（＝seed 以外が合っているかを見る対照）。

安全側の決めごとを4つ持っている。どれも壊れても例外にならず、静かに意味が変わる種類のもの。

- **キューが空でなければ1件も投げない。** 他人の生成に混ざると、出た画像が
  どの投入によるものか履歴からしか辿れなくなる。
- **投げたか判らない候補を、自動で投げ直さない。** 「判らない」を「失敗」と混ぜて
  再送すると二重生成になり、**どちらが記録の再現なのか判らなくなる**。
- **組めない記録ではキューを一切触らない。** 投げてから気づくと半端なものが1件残る。
- **出す画像には試行の印を焼く。** ComfyUI が PNG へ書くのは `extra_pnginfo` の中身
  だけなので、そこへ入れておく。入れないと、出た画像を Unbake へ落とし直したときに
  「どの試行の何番目か」が失われる。

### 5. 振る・束ねる・順番を知る — **同じく、まだ画面に出ていない**

- **LoRA 強度の上書き**は記録とは別レイヤに持ち、組み立てる直前にだけ重ねる。
  **記録そのものは書き換えない**——書き換えると、比較の基準点が回を追うごとに動く。
  「元に戻す」はレイヤを消すだけで済む。
- **実行リスト**は、順番に回したい記録を名前付きで束ねる入れ物。複数持てる。
  旧い形（ただの配列）で保存されたものもそのまま読む——失うのは配列ではなく
  **並べ直した順番**なので。
- **モデルの共有度**は「このモデルを、ほかに何件の記録が要求しているか」。
  不足しているモデルを**落としたときに解ける記録の件数**で並べ替えるために要る。
  実測（346件・2026-08-20）で **317件を数えて508種のモデル・うち173種が2件以上で共有**。
  **数えられなかった29件は0件扱いにしない**——黙って除くと共有件数が過小に出て、
  「ほかは誰も要求していない」という測っていない断定が静かに混ざる。

> **「中核にある」は「使える」ではない。** この2節のものは `web/core/` に入り、
> 検査（実データを含む）が通っているが、**パネルからは呼べない**。Sweep の面を
> 作るときに一緒に配線する。

### 件数が増えても潰れないようにしてある

サイドバーは狭い。素直に並べると、記録が増えた分だけスクロールが伸びる。
そうならないように3つを組み合わせてある。

1. **判定ごとの件数を常に上に出す。** スクロールせずに全体の形が分かる。
2. **描く前に絞る。** 検索（モデル名・プロンプト・ファイル名）と判定フィルタ。
   外した判定も**件数は見え続ける**——0件と「隠した」を混ぜないため。
3. **狭いときは行数に上限を置く。** 残りは「ほか N 件 — 全画面で開く」として出す。
   **スクロール量がデータ量に比例しない**のがこの3番目の効果。

**切り替えは画面の種類ではなく器の幅で決まる。** 全画面を狭くすればサイドバーと
同じ挙動になるし、サイドバーを広げれば全部出る。

## 言語

**既定は英語。** ComfyUI の言語設定（`Comfy.Locale`）に従うので、
ComfyUI を日本語にしていればパネルも日本語になる。**独自の切替は持たない**
——持つと「アプリは日本語なのにこのパネルだけ英語」という状態が作れてしまう。

**ComfyUI が選べる12言語すべてに対応している** —
en / zh / zh-TW / ru / ja / ko / fr / es / ar / tr / pt-BR / fa。
持っていない言語の利用者は英語へ落ちるので、宿主の選択肢に合わせてある。
**アラビア語とペルシア語は右から左**に組み替わる（CSS は論理方向で書いてある）。

**右から左のときは文字送り（`letter-spacing`）を切る。** グリフの間に空きを入れると
アラビア文字の連綴が視覚的に切れ、合字が別の2字に見える（`tile.commercial.no` の
ar は「لا」）。切るのは訳文を出す要素だけで、系統の札や出力ファイル名の数字は
ラテン英数なのでそのまま。**新しく `letter-spacing` を足すと、対象か対象外かを
宣言するまで検査が赤くなる**（`tests/rtl_letter_spacing_test.mjs`）。

追加は `web/i18n/locales/` に1ファイル足して `index.js` へ1行書くだけで、
**鍵の過不足は検査が赤くする**（訳の抜けは例外ではなく「その行だけ別の言語」として
出るので、人の目には残らない）。

> **英語と日本語以外は母語話者の確認を通っていない。** 各カタログの
> `meta.reviewed` がそれを持っている。誤りを見つけたら直してほしい——
> 直したら `reviewed` を `true` にすること。技術語（checkpoint / LoRA / denoise /
> sampler / VAE）は各言語でそのまま借用しているので、直すべきは説明文のほうである。

**`Generation Record` / `Replay Manifest` / `Sweep` はどの言語でも訳さない。**
製品の語彙であって文章ではなく、訳すと同じ道具を使う人どうしで話が通じなくなる。
日本語で主語として書くときだけ「記録」を使う。

**再現できない理由の文まで、12言語すべてで訳してある。** 「なぜ再現できないか」「何を代わりに使ったか」は
このツールでいちばん読まれる文なので、そこが片方の言語にしか無いと道具として片肺になる。

> 移し替えが文言を変えていないことは、**実レシピ346件・13,251件の文言を
> 改修の前後で突き合わせて**確かめてある（日本語側の差分0件）。

## 入れ方

ComfyUI Manager から `ComfyUI-Unbake` を入れるか、`custom_nodes` へ置く。

```
ComfyUI/custom_nodes/ComfyUI-Unbake/
```

**キャンバスノードは1つも増えない。** 追加されるのはサイドバーのタブで、
同じ画面を全画面でも開ける（コマンド `Unbake: 全画面で開く`、`Esc` で閉じる）。
